# 2.4.10 セクション見出し（AAA）

## 達成基準の概要

- WCAG 2.2 達成基準 2.4.10「セクション見出し」（Section Headings）
- レベル **AAA**（最高の適合レベル）
- 原則2「操作可能（Operable）」> ガイドライン 2.4「ナビゲーション可能」に属する
- コンテンツがセクションに分かれている場合、**セクション見出しで整理**すること
- 長い文書の構成把握と、ページ内ナビを助ける

> **参照**
> - [WCAG 2.2 — Success Criterion 2.4.10 Section Headings](https://www.w3.org/TR/WCAG22/#section-headings)
> - [Understanding SC 2.4.10 Section Headings](https://www.w3.org/WAI/WCAG22/Understanding/section-headings.html)

## 達成基準の原文（要約）

- セクション見出しを用いてコンテンツを整理すること
- **注記1**：「見出し」は一般的な意味で使い、タイトルや、さまざまな種類のコンテンツに見出しを付ける他の方法も含む
- **注記2**：対象は文章内のセクション。UI コンポーネントは 4.1.2 の対象

> **参照**
> - [WCAG 2.2 — Success Criterion 2.4.10](https://www.w3.org/TR/WCAG22/#section-headings)

## セクションとは

- 関連する話題や考えを扱う、まとまりのある文章の一部分
- 1つ以上の段落で構成され、図・表・リスト・下位セクションを含みうる
- 「章」「トピック」「設定グループ」など、内容の切れ目がある単位

```text
セクションの例：
  長文ドキュメントの各章・各節
  メニューの「前菜」「サラダ」「メイン」
  設定画面の「通知」「プライバシー」「表示」

セクションになりにくい例：
  短い単一段落だけのお知らせ
  UI の個々のボタンやタブそのもの（→ 4.1.2）
```

> **参照**
> - [Understanding SC 2.4.10 — Key Terms: section](https://www.w3.org/WAI/WCAG22/Understanding/section-headings.html#dfn-section)

## なぜ AAA か

- すべての種類のコンテンツに適用できるわけではない
- 既存文書を Web に載せるとき、元に見出しがなければ後から付けられない場合がある
- 長い手紙のように、見出しを入れると不自然な文書もある
- それでも、セクションに分けられる文書では、理解とナビが大きく改善する

```text
見出しを入れにくい例：
  元の紙文書に見出しがなく、改変できない公開物
  私信・手紙形式の長文

見出しを入れやすい例：
  マニュアル、ガイド、ニュース記事、FAQ
  設定ページのグループ分け
```

> **参照**
> - [Understanding SC 2.4.10 — Intent](https://www.w3.org/WAI/WCAG22/Understanding/section-headings.html#intent)

## なぜ必要か

- スクリーンリーダー利用者は、セクションの切れ目と目的を把握しやすい
- 学習障害のある人は、ページ全体の構成を見出しから理解しやすい
- キーボード利用者は、見出しジャンプで目的の内容へ素早く移動できる
- ページの一部が更新される場合も、見出しで更新箇所へアクセスしやすい

> **参照**
> - [Understanding SC 2.4.10 — Benefits](https://www.w3.org/WAI/WCAG22/Understanding/section-headings.html#benefits)

## 視覚的な区切りだけでは不十分

- 罫線・枠・余白・太字だけでセクションを示しても、この基準の見出しにはならない
- 見出しは、内容の組織を明確に示す「取っ手」になる
- 見た目の装飾は補助にはなるが、見出しの代替にはならない

```html
<!-- 悪い例：見た目だけでセクションを示す -->
<div class="box">
  <p class="big-bold">配送について</p>
  <p>通常2〜3日でお届けします。</p>
</div>
<div class="box">
  <p class="big-bold">返品について</p>
  <p>到着後14日以内に返品できます。</p>
</div>
```

```html
<!-- 良い例：セクション見出しがある -->
<section>
  <h2>配送について</h2>
  <p>通常2〜3日でお届けします。</p>
</section>
<section>
  <h2>返品について</h2>
  <p>到着後14日以内に返品できます。</p>
</section>
```

## 手法1：見出しでページを整理する（G141）

- ページを論理的なセクションに分け、各セクションに見出しを付ける
- 長い文書では、章・節・項の階層を見出しレベルで表現する
- 見出しがあることで、目次や見出し一覧が使えるようになる

```html
<!-- 良い例：長文を見出しで整理 -->
<article>
  <h1>アクセシビリティ方針</h1>

  <h2>目的</h2>
  <p>...</p>

  <h2>対象範囲</h2>
  <p>...</p>

  <h2>適合目標</h2>
  <h3>レベル A</h3>
  <p>...</p>
  <h3>レベル AA</h3>
  <p>...</p>

  <h2>問い合わせ</h2>
  <p>...</p>
</article>
```

```text
良い例（メニュー）：
  前菜 / サラダ / スープ / メイン / デザート
  各コースがセクション見出しになっている

良い例（設定画面）：
  通知設定 / プライバシー / 表示
  関連する設定をグループ化し、各グループに見出し
```

> **参照**
> - [Technique G141: Organizing a page using headings](https://www.w3.org/WAI/WCAG22/Techniques/general/G141)
> - [Understanding SC 2.4.10 — menu / settings examples](https://www.w3.org/WAI/WCAG22/Understanding/section-headings.html#examples)

## 手法2：各セクション先頭に見出し要素を置く（H69）

- HTML では `h1`〜`h6` をセクション先頭に置く
- スクリーンリーダーの見出しジャンプや、ブラウザ拡張の目次で使える
- 1.3.1（情報および関係性）でも十分な手法として使われる
- 2.4.1（ブロックスキップ）の構造的スキップにも役立つ

```html
<!-- 良い例：セクション先頭が見出し -->
<main>
  <h1>今日の献立ガイド</h1>

  <section aria-labelledby="appetizers">
    <h2 id="appetizers">前菜</h2>
    <ul>
      <li>サラダ</li>
      <li>スープ</li>
    </ul>
  </section>

  <section aria-labelledby="entree">
    <h2 id="entree">メイン</h2>
    <ul>
      <li>ステーキ</li>
      <li>魚料理</li>
    </ul>
  </section>
</main>
```

```html
<!-- 良い例：設定ページのグループ見出し -->
<main>
  <h1>設定</h1>

  <h2>通知</h2>
  <label><input type="checkbox"> メール通知</label>

  <h2>プライバシー</h2>
  <label><input type="checkbox"> プロフィールを公開する</label>

  <h2>表示</h2>
  <label><input type="checkbox"> ダークモード</label>
</main>
```

> **参照**
> - [Technique H69: Providing heading elements at the beginning of each section of content](https://www.w3.org/WAI/WCAG22/Techniques/html/H69)
> - [wcag/1-3-1-info-and-relationships.md — 1.3.1 情報および関係性](./1-3-1-info-and-relationships.md)

## UI コンポーネントは対象外

- この基準は**文章内のセクション**が対象
- ボタン・タブ・メニュー項目などの UI 部品そのものは対象外
- UI の名前・役割・状態は 4.1.2 で扱う
- ただし、設定画面のように「文章／説明のまとまり」がある場合は、そのまとまりに見出しを付ける

```text
2.4.10 の対象：
  記事の各節
  FAQ の各カテゴリ
  設定の説明グループ

4.1.2 の対象：
  タブの名前
  アコーディオンのボタン名
  カスタムウィジェットの役割と状態
```

> **参照**
> - [WCAG 2.2 — Success Criterion 4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value)

## 1.3.1・2.4.6 との関係

| 達成基準 | 焦点 | 関係 |
|---|---|---|
| 1.3.1 情報および関係性 | 見出しの正しいマークアップ | 「見出しとして識別できるか」 |
| 2.4.6 見出しおよびラベル | 見出し文言の説明性 | 「文言が分かりやすいか」 |
| 2.4.10 セクション見出し | セクションに見出しがあること | 「見出しで整理されているか」 |

```text
役割の違い：
  2.4.10：セクションがあるなら、見出しで区切る（存在）
  2.4.6：見出しがあるなら、内容を説明する（質）
  1.3.1：見出しなら、見出し要素等でマークアップする（構造）

理想：
  セクションがある
  → 見出しを付ける（2.4.10）
  → 説明的にする（2.4.6）
  → 正しくマークアップする（1.3.1）
```

> **参照**
> - [wcag/2-4-6-headings-and-labels.md — 2.4.6 見出しおよびラベル](./2-4-6-headings-and-labels.md)

## 実装時の注意点

- 長いページほど、セクション見出しの効果が大きい
- 見出しレベルは論理階層に合わせ、見た目のためだけに飛ばさない
- `h1` はページ全体の主題、以降はセクションの入れ子に対応させる
- 装飾用の太字テキストを見出しの代わりにしない
- 既存文書を公開するときは、可能な範囲で見出しを補うか、最初から構造化して作成する

```text
実務チェック：
  長文ページを見出し一覧だけでスキャンできるか
  関連トピックごとに見出しがあるか
  罫線や枠だけで区切っていないか
  設定やメニューのグループにも見出しがあるか
```

## テスト・確認方法

### 手動テスト

- ページが複数の話題・章・グループに分かれているか確認する
- 分かれている場合、各セクション先頭に見出しがあるか確認する
- 見出し一覧（スクリーンリーダーや拡張機能）で構成が伝わるか確認する
- 見た目だけの区切りに頼っていないか確認する
- UI 部品そのものと、文章セクションを混同していないか確認する

```text
チェックリスト：
1. コンテンツにセクションがあるか
2. 各セクションに見出しがあるか
3. 見出しはマークアップされているか（1.3.1）
4. 見出し文言は説明的か（2.4.6）
5. 視覚的な区切りだけになっていないか
```

### 開発者ツールでの確認

```bash
# 見出しと、見出しっぽい装飾クラスを探す
rg "<h[1-6]|role=\"heading\"|class=\".*(title|heading|section)" --glob "*.html" --glob "*.tsx" --glob "*.jsx" --glob "*.php"
```

```javascript
// Console：見出し一覧
[...document.querySelectorAll("h1,h2,h3,h4,h5,h6,[role='heading']")]
  .map((el) => `${el.tagName.toLowerCase()}: ${el.textContent.trim()}`)
```

> **参照**

## まとめ

- 2.4.10 は、コンテンツがセクションに分かれているとき、**セクション見出しで整理する**ことを求める達成基準（レベル AAA）
- 対象は文章内のセクションで、UI コンポーネント自体は 4.1.2 の領域
- 視覚的な区切りだけでは不十分。見出し要素などで明示する
- 主な手法は、見出しによるページ整理（G141）と、セクション先頭の見出し要素（H69）
- 2.4.6（説明性）と 1.3.1（マークアップ）と併せて、存在・質・構造をそろえる
