# 3.1.3 一般的でない用語（AAA）

## 達成基準の概要

- WCAG 2.2 達成基準 3.1.3「一般的でない用語」（Unusual Words）
- レベル **AAA**（最高の適合レベル）
- 原則3「理解可能（Understandable）」> ガイドライン 3.1「読みやすさ」に属する
- 慣用句・専門用語など、**普通でない／限定された意味**で使う語や句について、定義を特定できる仕組みがあること
- 辞書に複数の意味がある語で、特定の意味を選ばないと内容が通じない場合も対象

> **参照**
> - [WCAG 2.2 — Success Criterion 3.1.3 Unusual Words](https://www.w3.org/TR/WCAG22/#unusual-words)
> - [Understanding SC 3.1.3 Unusual Words](https://www.w3.org/WAI/WCAG22/Understanding/unusual-words.html)

## 達成基準の原文（要約）

- 慣用句および専門用語を含め、普通でない、または限定された方法で使われている語や句の、特定の定義を識別する仕組みがあること

> **参照**
> - [WCAG 2.2 — Success Criterion 3.1.3](https://www.w3.org/TR/WCAG22/#unusual-words)

## なぜ必要か

- 認知・言語・学習障害のある人は、比喩や専門的な使い方を取り違えやすい
- 語の復号（デコード）や、句全体の意味把握が難しい人の助けになる
- 画面拡大で周囲の文脈が見えにくい視覚障害のある人にも、定義への導線が役立つ
- 専門家向けでない読者に専門情報を出すとき、A / AA だけでも満たしておくことが推奨される
- 造語・新語も免除されない。分かりにくければ定義が必要

> **参照**
> - [Understanding SC 3.1.3 — Benefits](https://www.w3.org/WAI/WCAG22/Understanding/unusual-words.html#benefits)

## 対象になる語・句

- **普通でない／限定された使い方**：正しい理解のために、特定の定義を選ぶ必要がある使い方
- **慣用句（idiom）**：個々の語の意味から全体が導けず、語を変えると意味が壊れる句
- **専門用語（jargon）**：特定の分野の人が、その分野特有の意味で使う語
- 辞書の一般的な意味ではなく、そのページで決めた意味で使う語
- 作者は、**想定読者**と前後の文脈を踏まえて判断してよい

```text
対象になりやすい例：
  WCAG の「テキスト」「技術」のように、文書内で意味を狭めている語
  慣用句：「さじを投げる」（あきらめる）
  専門用語：プリンタの「ドライバ」（ソフトウェア）
  カタカナの外来語で、読者に馴染みがないもの
  フロントエンドの「ハイドレーション」（HTML にイベントを結びつけること）

対象になりにくい例：
  想定読者が同じ定義を共有している、ごく一般的な語
  文脈から一意に分かる、曖昧さが残らない語
```

> **参照**
> - [Understanding SC 3.1.3 — Key Terms](https://www.w3.org/WAI/WCAG22/Understanding/unusual-words.html)
> - [Technique G101: Providing the definition of a word or phrase used in an unusual or restricted way](https://www.w3.org/WAI/WCAG22/Techniques/general/G101)

## 初出だけか、毎回か

- **ページ内で意味が1つ**なら、初出で定義すれば足りる（毎回でもよい）
- **同じページで意味が複数**なら、出現のたびに定義が必要
- 仕組みはコンテンツ内でも、依存するユーザーエージェントでもよい。ただし主張する適合レベルの他基準も満たすこと

```text
初出で足りる例：
  用語集へリンクし、そのページでは常に同じ意味で使う

毎回必要な例：
  同じページで「カスケード」を
    1. CSS の詳細度の仕組み
    2. 辞書の検索順
  の両方で使う
```

> **参照**
> - [Understanding SC 3.1.3 — Sufficient Techniques](https://www.w3.org/WAI/WCAG22/Understanding/unusual-words.html)

## 手法1：文中で定義する（G112 + H54）

- **G112**：語の直後や同じ文で定義を示す
- **H54**：定義している出現箇所を `<dfn>` で囲む（定義文ではなく、用語側）
- 括弧書きも、日本語の慣用句・外来語でよく使う形

```html
<!-- 良い例：dfn とインライン定義 -->
<p>
  WCAG は、非テキストコンテンツにテキストによる代替を求めます。
  <dfn>非テキストコンテンツ</dfn>とは、プログラムで判定できる文字の並びではないコンテンツ、
  または人間の言語として意味を持たない文字列です。
</p>
```

```html
<!-- 良い例：慣用句を括弧で定義（G101 の日本語例） -->
<p>さじを投げる（どうすることもできなくなり、あきらめること）。</p>
```

```html
<!-- 良い例：馴染みのない外来語 -->
<p>
  アクセシビリティ（高齢者・障害者を含む全ての人が利用できること）は、
  Webサイトに不可欠である。
</p>
```

```html
<!-- 悪い例：専門的な使い方なのに説明がない -->
<p>ハイドレーションが完了するまで操作しないでください。</p>
```

```html
<!-- 良い例 -->
<p>
  <dfn>ハイドレーション</dfn>（サーバが出力した HTML に、クライアントでイベント処理を結びつけること）
  が完了するまで操作しないでください。
</p>
```

> **参照**
> - [Technique G112: Using inline definitions](https://www.w3.org/WAI/WCAG22/Techniques/general/G112)
> - [Technique H54: Using the dfn element to identify the defining instance of a word or phrase](https://www.w3.org/WAI/WCAG22/Techniques/html/H54)

## 手法2：定義へリンクする（G55） / 用語集を置く（G62）

- **G55**：定義（ページ内・用語集・辞書）へリンクする
- **G62**：用語集を提供する
- 説明リスト（`<dl>`）で用語と定義を対にする方法もある（H40）

```html
<!-- 良い例：初出を用語集へリンク -->
<p>
  WCAG 2 では
  <a href="#def-text"><dfn>テキスト</dfn></a>
  を特定の意味で使います。
</p>

<h2>用語集</h2>
<dl>
  <dt id="def-text">テキスト</dt>
  <dd>
    プログラムで判定できる文字の並びで、人間の言語として何かを表しているもの。
  </dd>
</dl>
```

```html
<!-- 悪い例：用語集はあるが、本文から辿れない -->
<p>この仕様の「テキスト」は限定された意味です。</p>
<!-- ページ末尾に定義があるが、リンクも案内もない -->
```

> **参照**
> - [Technique G55: Linking to definitions](https://www.w3.org/WAI/WCAG22/Techniques/general/G55)
> - [Technique G62: Providing a glossary](https://www.w3.org/WAI/WCAG22/Techniques/general/G62)
> - [Technique H40: Using description lists](https://www.w3.org/WAI/WCAG22/Techniques/html/H40)

## 手法3：オンライン辞書を検索できる（G70）

- サイト内、または依存できる辞書検索で、意図した定義に辿れること
- 複数辞書がある場合は、意図した定義が先に出る順にする（Understanding の cascade の例）
- 一般向けサイトでは、インライン定義や用語集の方が確実なことが多い

> **参照**
> - [Technique G70: Providing a function to search an online dictionary](https://www.w3.org/WAI/WCAG22/Techniques/general/G70)

## 3.1.4 との関係

| 達成基準 | レベル | 対象 |
|---|---|---|
| 3.1.3 一般的でない用語 | AAA | 慣用句・専門用語・限定された意味の語 |
| 3.1.4 略語 | AAA | 略語・頭字語の元の語や定義 |

- 略語の展開は 3.1.4。専門的な意味そのものの説明は 3.1.3
- 両方に当てはまることもある（例：専門分野の頭字語を、展開と定義の両方で示す）

## よくある失敗例

- 業界用語を、読者向け説明なしに本文へ並べる
- `title` だけで定義し、キーボードやタッチでは辿れない
- 用語集があるが、本文の語からリンクしていない
- 同じページで意味が複数あるのに、初出の定義だけしかない
- 造語・プロダクト固有の呼び方を、一般語のように使う

```html
<!-- 失敗例：title 依存（辿れないユーザーがいる） -->
<span title="サーバが出力した HTML にイベントを結びつけること">ハイドレーション</span>
```

```html
<!-- 改善例：テキストとして定義が見える -->
<p>
  <dfn>ハイドレーション</dfn>とは、サーバが出力した HTML に
  クライアントでイベント処理を結びつけることです。
</p>
```

## テスト・確認方法

### 手動テスト

- 想定読者の立場で、慣用句・専門用語・限定用法を洗い出す
- 各語に、定義へ辿る仕組みがあるか確認する
- 意味が1つか複数かで、初出だけで足りるか判断する
- 造語・カタカナ外来語・プロダクト用語も漏らさない

```text
チェックリスト：
1. 普通でない／限定された使い方の語・句はあるか
2. 慣用句・専門用語・造語はあるか
3. 定義が文中、用語集、または辞書検索で辿れるか
4. ページ内で意味が複数なら、出現ごとに辿れるか
5. 定義がスクリーンリーダーやキーボードでも辿れるか
6. 略語なら 3.1.4 も見ているか
```

> **参照**
> - [a11y/manual-testing-checklist.md — 手動テストチェックリスト](../a11y/manual-testing-checklist.md)

## まとめ

- 3.1.3 は、慣用句・専門用語など**普通でない／限定された意味**の語について、定義を特定できる仕組みを求める達成基準（レベル AAA）
- 文中定義（`<dfn>`）、用語集へのリンク、説明リストなどが典型的な手法
- ページ内の意味が1つなら初出で足りる。複数なら出現ごとに必要
- 想定読者と文脈で判断してよいが、造語や新語は免除されない
- 略語の展開は 3.1.4。専門的な意味の説明はこの基準
