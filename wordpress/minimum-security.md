## wp2shellによる攻撃

- タイトル: WordPressの脆弱性対策について(CVE-2026-60137、CVE-2026-63030：wp2shell)
- URL: https://www.ipa.go.jp/security/security-alert/2026/alert20260722.html
- 概要:
  - WordPress Core の脆弱性（CVE-2026-60137 / CVE-2026-63030）を組み合わせた攻撃チェーンの通称が wp2shell
  - 標準構成でも管理者権限なしに遠隔コード実行に至る可能性があり、修正版への更新が求められている

保守から担当している案件の一つで攻撃を確認した
不審なユーザーが作成されていることを発見

## サイトの状態
一般的にいわれているセキュリティ対策を何もしていなかった
セキュリティ系のプラグインも入っていなかった
バックアップを取っていなかった
不正なユーザーが作成される前の状態に切り戻すことができなかった

## 対策
### バージョンアップ
6.9.4から6.9.5へバージョンアップ

### パスワードの変更
管理画面にログインできるユーザーのパスワードを変更
DBのパスワードを変更

### 侵入経路の遮断
/wp/wp-json/が侵入経路
非ログインユーザーの上記URLへのアクセスを遮断

### 管理画面への不正ログインを防ぐ
siteguardを使用
ログインURLを変更
ひらがなの画像認証を加える

### バックアップを作成
wpvividを使用
1週間単位で4週分のバックアップを保持

### 監視
アクティビティログを使用
不正なログインやファイル操作がないことを監視


## よりよい対策は

### WAF
- WAF（Web Application Firewall）で悪意あるリクエストをアプリ到達前に遮断する
- レンタルサーバ付帯や Cloudflare などの導入が現実的
- REST API への異常アクセスや既知の攻撃パターンの遮断に有効
- SiteGuard などのアプリ内対策と併用する上位レイヤとして位置づける

### WordPress以外のCMS・構成
- WordPress はシェアが大きく攻撃対象になりやすい
- 公開面に管理画面や PHP 実行環境を置かない構成を検討する — 例: Astro などの静的サイト + ヘッドレスCMS
- 更新頻度が低いコーポレートサイトでは攻撃面を大きく減らせる
- 動的機能が必須なら WordPress 継続 + 本記事の最低限対策 + WAF が現実的
