# 見出しはヘッダーではなくmainタグにいれるべきなのか

## 見出しとランドマークとは

- 日本のX（旧Twitter）で、ページの見出しをヘッダーではなく`<main>`に入れるべきかという議論を見かけた
- 私はこれまで、トップページではヘッダーのロゴを`<h1>`にし、下層ページではページタイトルを`<h1>`にしていた
- この方法ではダメなのかと気になったため、HTMLの仕様とWCAG 2.2（ウェブコンテンツのアクセシビリティガイドライン）を確認した
- 先に結論を書くと、トップページのロゴを`<h1>`にしているという理由だけで、WCAG違反とは判断できない
- 一方、ページ固有のタイトルを`<main>`の先頭付近に置く構成には、本文へ移動した人が主題を把握しやすいという利点がある
- 見出しは、内容の主題と階層を表すもの — HTMLでは`<h1>`から`<h6>`を使い、スクリーンリーダーでは見出し単位の移動にも利用できる
- ランドマークは、ページ内の主要な領域を示すもの — サイト全体のヘッダーを示す`banner`や、主要な内容を示す`main`などがある
- 見出しを探す操作と、本文の領域へ移動する操作は別にあるため、両方からページを把握できる構成を考えたい
- この記事では主にページの最上位見出しである`<h1>`を扱う — すべての見出しを`<main>`に集めるという話ではない
- 情報の確認日は2026年10月20日

> 参照: [W3C WAI — Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/) / [W3C WAI — Page Regions](https://www.w3.org/WAI/tutorials/page-structure/regions/)

## なぜページの見出しをmainに置くのか

- `<main>`は、その文書の主要な内容を表す要素
- ページタイトルをその先頭付近に置けば、本文の領域へ移動したあと、タイトルから内容を読み進められる
- ページタイトルがサイト共通の`<header>`にあると、`<main>`へのスキップリンクやランドマーク移動で、そのタイトルを飛び越える場合がある
- たとえば「採用情報」というタイトルを通り過ぎて、いきなり募集職種の説明から読み始める構成になる
- こうした場合に、本文の入口とページタイトルをそろえる方法として、`<main>`内への配置が役立つ
- これは利用時のわかりやすさについての判断であり、配置だけを根拠にWCAGの合否を決める話とは分けて考える

```html
<!-- 改善前：mainへ移動すると、ページタイトルを飛び越える構成 -->
<header>
  <a href="/">Example株式会社</a>
  <h1>採用情報</h1>
</header>

<main id="main-content">
  <p>現在募集している職種を紹介する</p>
</main>
```

```html
<!-- 良い例：本文の入口で、ページの主題を確認できる -->
<a href="#main-content">本文へスキップ</a>

<header>
  <a href="/">Example株式会社</a>
</header>

<main id="main-content" tabindex="-1">
  <h1>採用情報</h1>
  <p>現在募集している職種を紹介する</p>
</main>
```

- この例のスキップリンクは常時表示する想定 — CSSで普段は隠す場合も、キーボードフォーカス時には表示する
- `tabindex="-1"`は移動先をフォーカス可能にし、通常のTab移動順には加えない指定 — 実装後は対象のブラウザーでリンク実行後のフォーカスと読み進める位置を確認する

> 参照: [WHATWG — The main element](https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element) / [WCAG 2.2 — 2.4.1「ブロックスキップ」の解説](https://www.w3.org/WAI/WCAG22/Understanding/bypass-blocks.html)

## WCAGは何を求めているのか

- WCAG 2.2には「`<h1>`は必ず`<main>`の中に置く」「トップページのロゴを`<h1>`にしてはいけない」という直接の規定はない
- 確認するのは、見出しの構造や文言、繰り返し部分を飛ばす仕組みなど、個々の達成基準で求められる内容
- W3Cのチュートリアルや達成方法集に載っている実装例と、適合のための必須条件は同じではない — 達成方法集も、掲載された方法の使用自体は必須ではないと説明している

> 参照: [W3C — WCAG 2.2](https://www.w3.org/TR/WCAG22/) / [WCAG 2.2 — G141「見出しを用いてページを構成する」](https://www.w3.org/WAI/WCAG22/Techniques/general/G141)

### 1.3.1「情報及び関係性」— レベルA

- 見た目などで伝わる情報・構造・関係性を、プログラムで判断できるようにするか、テキストで提供するという基準
- 見出しとして表示しているテキストを、大きさや太さだけで表現していないかが確認点になる
- 見出しには`<h1>`〜`<h6>`を使い、内容の親子関係が伝わるレベルを選ぶ
- ページタイトルを`<main>`へ移しても、見出しとしての意味が伝わらないままでは、構造の問題は解決しない

```html
<!-- 悪い例：見出しを見た目だけで表現している -->
<p style="font-size: 2rem; font-weight: bold;">採用情報</p>

<!-- 良い例：ページの主題を見出し要素で表現する -->
<h1>採用情報</h1>
```

> 参照: [WCAG 2.2 — 1.3.1「情報及び関係性」の解説](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)

### 2.4.6「見出し及びラベル」— レベルAA

- 見出しやラベルが、主題または目的を説明していることを求める基準
- 「採用情報」「募集職種」「選考の流れ」のように、続く内容を予測できるかを確認する
- この基準だけで、見出しの設置自体や、`<h1>`の個数・配置を指定しているわけではない
- 見出しとして適切にマークアップされているかは1.3.1、見出しの文言が内容を説明しているかは2.4.6という違いがある

> 参照: [WCAG 2.2 — 2.4.6「見出し及びラベル」の解説](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html)

### 2.4.1「ブロックスキップ」— レベルA

- 複数のページで繰り返すコンテンツのまとまりを、飛ばせる仕組みを求める基準
- サイト共通のヘッダーやナビゲーションを毎回たどらず、本文へ進めるかが確認点になる
- スキップリンクはその実装方法の一つ — 達成方法集にはランドマークを利用する方法なども挙げられている
- 「スキップ先でページタイトルから読めるようにする」という設計は、この移動をわかりやすくするための工夫と考えられる
- ただし、スキップで`<h1>`を通り過ぎるという事実だけで、この基準の違反が確定するわけではない

> 参照: [WCAG 2.2 — 2.4.1「ブロックスキップ」の解説](https://www.w3.org/WAI/WCAG22/Understanding/bypass-blocks.html)

### 関連する2.4.2と2.4.10

- 2.4.2「ページタイトル」（レベルA）は、ページに主題や目的を説明するタイトルがあることを求める — HTMLでは`<title>`による文書タイトルを確認する
- 画面に表示する`<h1>`と、`<head>`内の`<title>`は別の要素 — `<h1>`があっても、文書タイトルの確認は必要になる
- 2.4.10「セクション見出し」（レベルAAA）は、セクション見出しを使ってコンテンツを整理することを求める
- 2.4.10をレベルAAの必須条件として扱ったり、`<h1>`の配置を指定する基準として扱ったりしない

> 参照: [WCAG 2.2 — 2.4.2「ページタイトル」の解説](https://www.w3.org/WAI/WCAG22/Understanding/page-titled.html) / [WCAG 2.2 — 2.4.10「セクション見出し」の解説](https://www.w3.org/WAI/WCAG22/Understanding/section-headings.html)

## トップページだけロゴをh1にする方法ではダメなのか

- 私が使っていた「トップページはロゴ、下層ページはページタイトルを`<h1>`にする」という方針も、それだけで不適合になるものではない
- WHATWGのHTML仕様にも、サイト名を`<header>`内の`<h1>`にし、`<main>`内を`<h2>`から始める例がある
- W3C WAIの見出しチュートリアルも、サイト名を最上位見出しにする構成と、本文の見出しを最上位にする構成の両方を紹介している
- ただし、仕様やチュートリアルに例があることは、その形にすればページ全体がWCAGに適合するという保証ではない
- トップページでサイト名がページ全体の主題として機能し、本文の見出しとの関係も理解できるかを確認する必要がある

```html
<!-- 従来の例：トップページだけサイト名をh1にする -->
<header>
  <h1>
    <a href="/">
      <img src="/logo.svg" alt="Example株式会社">
    </a>
  </h1>
</header>

<main>
  <h2>事業紹介</h2>
  <p>Webサイトの制作と運用を支援する</p>
  <h2>お知らせ</h2>
  <p>最新の情報を掲載する</p>
</main>
```

- この構成を見直すなら、ロゴのタグだけを切り替えるルールよりも、トップページの主題をどう伝えるかから考えたい
- たとえばロゴは共通のリンクにし、`<main>`の先頭でサイト名や事業内容を`<h1>`として示す方法がある
- この方法なら、トップページでも下層ページでも、本文へ移動した位置から主題を確認できる
- サイト名を`<h1>`にすること自体は変えず、置く場所を`<main>`内にする選択もできる

```html
<!-- 見直す場合の例：ロゴは共通リンク、本文の主題はmain内のh1 -->
<header>
  <a href="/">
    <img src="/logo.svg" alt="Example株式会社">
  </a>
</header>

<main>
  <h1>Example株式会社のWeb制作・運用支援</h1>
  <p>企画から公開後の改善まで、Webサイトの運用を支援する</p>
  <h2>事業紹介</h2>
  <p>提供しているサービスを紹介する</p>
</main>
```

- 下層ページでページタイトルを`<h1>`にする方針は、そのまま使いやすい — あわせて`<main>`内にあるかを確認する
- 新しく作るサイトでは、トップページも含めてページの主題を`<main>`内の`<h1>`で示す構成を基本にしたい
- 既存サイトはロゴの`<h1>`だけで修正を決めず、見出し一覧と本文への移動を確認し、具体的にわかりにくい部分から見直す

> 参照: [WHATWG — The main elementの実装例](https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element) / [W3C WAI — Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/)

## よくある間違い

### 1. headerの中には見出しを置けないと考える

- `<header>`は導入的な内容やナビゲーションをまとめる要素であり、見出しを含められる
- サイト共通のヘッダーと、記事のタイトル・公開日などをまとめるヘッダーは役割が異なる
- `<main>`内の記事に`<header>`を置き、その中に`<h1>`を入れる構成も使える — `header`と`main`は二者択一ではない
- 以下の外側の`<header>`は`banner`ランドマークになる一方、記事内の`<header>`はサイト全体の`banner`にはならない

```html
<!-- 良い例：サイト共通のヘッダーと記事のヘッダーを分ける -->
<header>
  <a href="/">制作メモ</a>
</header>

<main>
  <article>
    <header>
      <h1>見出しはヘッダーではなくmainタグにいれるべきなのか</h1>
      <p>公開日：<time datetime="2026-10-20">2026年10月20日</time></p>
    </header>
    <p>記事の本文が続く</p>
  </article>
</main>
```

> 参照: [WHATWG — The header element](https://html.spec.whatwg.org/multipage/sections.html#the-header-element) / [W3C — HTML Accessibility API Mappingsのheaderの定義](https://www.w3.org/TR/html-aam-1.0/#el-header)

### 2. h1をmainに入れるため、サイト共通ヘッダーごと移す

- 主要な内容を表す`<main>`に、サイト共通のロゴやナビゲーションまでまとめて入れる必要はない
- サイト共通のヘッダーは外側に残し、ページ固有のタイトルや導入文を`<main>`に含める構成を考える
- `<main>`の内側にある`<header>`は、サイト全体の`banner`ランドマークにはならないため、移動前後で領域の意味も確認する

> 参照: [WHATWG — The main element](https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element) / [W3C — HTML Accessibility API Mappingsのheaderの定義](https://www.w3.org/TR/html-aam-1.0/#el-header)

### 3. h1の個数や位置だけでWCAGの合否を決める

- ページの主題を示す`<h1>`を一つにすると、見出しの構造を整理しやすい
- ただし「一つなら適合」「二つなら不適合」という個数だけの判定はしない
- 見出しの文言と階層が内容を表しているか、本文へ移動してページの主題を理解できるかを確認する
- 見出し一覧からたどる操作、`main`ランドマークへ移動する操作、キーボードでスキップリンクを使う操作をそれぞれ確認したい

> 参照: [W3C WAI — Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/) / [WCAG 2.2 — 2.4.6「見出し及びラベル」の解説](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html)

## まとめ

- WCAG 2.2には、`<h1>`を必ず`<main>`に入れるという直接の規定はない
- トップページだけヘッダーのロゴを`<h1>`にする方法も、それだけで不適合とは判断できない
- ページ固有のタイトルを`<main>`の先頭付近に置くと、本文へ移動したあとに主題を把握しやすい
- 見出しの構造は1.3.1、文言は2.4.6、繰り返し部分を飛ばす仕組みは2.4.1というように、確認する観点を分ける
- `<header>`には見出しを置ける — `<main>`内の記事ヘッダーに`<h1>`を入れる構成も使える
- 新規制作ではページの主題を`<main>`内の`<h1>`で示す構成を基本にし、既存サイトでは実際の見出し構造と移動後のわかりやすさを確認して判断したい
