# WordPressとmicroCMS — セキュリティ対策とランニングコストで比べる

## WordPressとmicroCMSとは

- WordPress は PHP で動く CMS — テーマとプラグインで画面と機能を足す。管理画面と公開サイトを同じサーバーに置く構成がまだ多い
- microCMS は日本製のヘッドレス CMS — 入稿画面と API を提供し、見た目は Astro や Next.js など別のフロントエンドが描く
- この記事で比べる WordPress は、レンタルサーバーに自分で入れるもの（wordpress.org のソフトウェア）— WordPress.com の有料プランとは別物
- 比べる軸は2つ — どこを守るか、毎月いくらか
- ソフトウェアが無料であることと、運用が安いことは別 — WordPress のライセンスは 0 円でも、更新と障害対応の時間は残る
- microCMS に替えると公開面の PHP は消せる — 管理画面のアカウント、API キー、フロントの依存関係は残る

> 参照: [microCMS 料金プラン](https://microcms.io/pricing) / [WordPress.org](https://wordpress.org/)

## 攻撃面の違い

- 攻撃面は、インターネットから届くリクエストが実行される場所 — そこが広いほど、更新漏れと設定ミスの影響が大きい
- WordPress を同一サーバーで動かすと、公開オリジンに PHP、データベース、`/wp-admin/`、`/wp-login.php`、REST API（`/wp-json/`）が乗る
- プラグインとテーマはそれぞれが PHP を追加する — 本体を更新しても、止めたプラグインの脆弱性は残る
- 侵入されると、ファイルの書き換え、管理者ユーザーの追加、データベースの抜き取りが同じサーバー上で起きうる
- microCMS をビルド時に取り込む静的サイトでは、公開オリジンは HTML と CSS と JS — 管理画面は `microcms.io` 側にあり、PHP もデータベースも公開サーバーに置かない
- 残る境界は API — キーの権限、下書きの取得、Webhook、プレビュー用の `draftKey`
- ブラウザから API を叩く構成（CSR）では、キーが利用者の手元に渡る — 公式も、キーとエンドポイントが分かると権限の範囲で API を呼べると注意している
- リッチエディタの HTML をそのまま描画するなら、XSS はフロントの責任として残る — CMS を替えても入力の出力先は自分の画面

```js
// 悪い例：WRITE や下書き全取得が付いたキーを、ブラウザへ出る接頭辞で渡す
const client = createClient({
  serviceDomain: import.meta.env.PUBLIC_MICROCMS_SERVICE_DOMAIN,
  apiKey: import.meta.env.PUBLIC_MICROCMS_API_KEY,
});

// 良い例：本番は GET のみのキーをビルド時に使う
// Astro では PUBLIC_ の付かない環境変数は、クライアントの束ねたファイルに出ない
const client = createClient({
  serviceDomain: import.meta.env.MICROCMS_SERVICE_DOMAIN,
  apiKey: import.meta.env.MICROCMS_API_KEY,
});
```

> 参照: [APIキー（APIの認証と権限管理）](https://document.microcms.io/content-api/x-microcms-api-key) / [APIキーを隠す必要はありますか？](https://help.microcms.io/ja/knowledge/hide-api-key)

## 対策の担当範囲

- WordPress は、サーバー、PHP、コア、プラグイン、テーマ、アカウント、バックアップを自分（または保守契約の相手）が持つ
- microCMS は、入稿基盤の可用性と基盤側の更新をベンダーが持つ — フロントのビルド、キー、公開内容の正しさは自分のまま
- 同じ「ログインを守る」「権限を分ける」でも、機能が標準か、プランの上位か、プラグインかで月額が変わる — 金額は次の節

| 項目 | WordPress（管理画面を公開サーバーに置く） | microCMS + 静的配信 |
|---|---|---|
| 公開面で動くもの | PHP、データベース、管理画面 | ビルド済みのファイル。API はビルド時かサーバー側 |
| 本体の更新 | コア、プラグイン、テーマ、PHP を自分で上げる | CMS 本体はベンダー。フロントのライブラリは自分 |
| ログイン | `wp-login.php`。URL 変更や画像認証は SiteGuard などのプラグイン。2要素認証もプラグインで足す | microCMS のアカウント。2要素認証の設定自体は全プランで可能。アカウントへの必須化は Enterprise |
| 権限の分離 | 管理者、編集者、投稿者などのロールが標準 | 権限管理は Business 以上 |
| 管理画面の IP 制限 | サーバー、WAF、プラグインで足す | 管理画面と API の IP 制限は Business 以上 |
| 監査ログ | プラグインやサーバーのログ | Enterprise |
| SSO | プラグインと IdP の組み合わせ | Enterprise（SAML） |
| バックアップ | サーバー機能かプラグイン。世代を残す作業は自分 | コンテンツの保管はベンダー。過去バージョンの復元は Business 以上。フロントの履歴は Git |
| 秘密情報 | `wp-config.php` の DB パスワード、ソルト | API キー。GET と WRITE を分ける |
| WAF | 公開オリジンの前段に置く意味が大きい。国内レンタルサーバーは標準搭載が多い | 静的配信では PHP へのリクエストが無い。自前フォームのエンドポイントは別に守る |

- WordPress 側の最低限は、コアとプラグインの更新、ログインの強化、WAF、バックアップ、操作ログ — 詳細は別記事に分けている
- microCMS 側の最低限は、本番キーを GET のみにする、下書き全取得を本番キーに付けない、WRITE キーをブラウザと公開リポジトリに置かない、プレビューは下書き用の経路だけに閉じる

> 参照: [microCMS 料金プラン — セキュリティ機能の比較](https://microcms.io/pricing) / [WordPressの最低限のセキュリティ対策](../wordpress/minimum-security.md)

## ランニングコスト

- 比べる単位は CMS の月額だけにしない — サーバーまたは配信、セキュリティ機能がどのプランに入っているか、更新に使う時間、を同じ表に載せる
- 以下の金額は 2026年10月時点の公開情報 — microCMS は税抜（2025年6月10日改定）。レンタルサーバーは各社の月額表示で、税の扱いが microCMS と揃っていない。桁の比較として読む
- 制作費、テーマ、独自デザインの初期構築は含まない — ここにあるのは運用で毎月かかる分
- ドメインと SSL はどちらも年 1,000 円前後か、サーバーとホスティングの無料特典に収まることが多い — 月額の差の本体にはなりにくい

### 料金が乗る場所

| 費用 | WordPress（自前インストール） | microCMS + 静的配信 |
|---|---|---|
| CMS の利用料 | 0 円（GPL） | Hobby **0 円** / Team **4,900 円** / Business **75,000 円** / Enterprise は見積もり（いずれも月額・税抜） |
| サーバー・配信 | レンタルサーバーが要る。エックスサーバーのスタンダードは、36ヶ月契約で月額 **990 円**、3ヶ月契約で月額 **1,320 円**（キャンペーン除く公式料金） | 静的ホスティングを別に持つ。Cloudflare Pages の無料枠は帯域無制限、ビルドは月 **500** 回 |
| WAF | 国内の共有サーバーでは標準のことが多い。クラウド型を足すと月額数千円から | 静的ファイルへの WAF 需要は小さい。フォーム用の API を自前で持つならその分は別 |
| セキュリティ用プラグイン | SiteGuard WP Plugin は無料。スキャンや有料シグネチャが要る製品は年額が発生する | CMS にプラグインは無い |
| 権限・IP 制限・監査 | ロールは追加ライセンスなし。IP 制限と監査はサーバー設定かプラグイン | 権限管理と IP 制限は Business 以上。監査ログ、2要素認証の必須化、SSO、請求書払いは Enterprise |
| 更新の作業 | 本体、プラグイン、テーマ、PHP が継続作業 | CMS 本体のアップデート作業はベンダー側。フロントの依存パッケージは残る |

- プランは 1 サービス（`***.microcms.io`）ごとに 1 つ — サイトを増やすと CMS 利用料もサービス数ぶん増える
- 支払いは月払い — 年払い割引は無い
- 無料トライアルは 1 サービスにつき 1 回、14 日間

### 規模ごとの月額

- インフラと CMS の現金だけを置く — 人の時間は次の小節
- 配信は Cloudflare Pages の無料枠に収まる更新頻度を仮定している — ビルド月 500 回を超える、SSR やサーバー処理を常時載せる、といった構成は配信側も有料になる
- Vercel の Hobby は商用条件が別 — 案件の配信先は、無料枠の商用可否をプランページで確認する

| 想定 | 構成 | 月額の目安 | 年額の目安 |
|---|---|---|---|
| 個人の検証、公開されても困らない内容 | microCMS Hobby + 静的配信の無料枠 | **0 円** | **0 円** |
| 同上 | WordPress + スタンダード級のレンタルサーバー | **990〜1,320 円** | **約 1.2〜1.6 万円** |
| コーポレート 1 本、更新 3 人まで、権限分離は要らない | microCMS Team（API 10 個・メンバー 3 人まで）+ 無料枠の配信 | **4,900 円** | **58,800 円** |
| 同上 | WordPress + スタンダード級 | **990〜1,320 円** | **約 1.2〜1.6 万円** |
| API を 13 個に分ける（Team の 10 個を 3 個超過） | Team + API 追加 | **10,900 円** | **130,800 円** |
| 書く人とは別に公開者を置きたい、社外 IP から管理画面を閉めたい | microCMS Business | **75,000 円〜** | **90 万円〜** |
| 同上を WordPress のロールとサーバー側の IP 制限で行う | WordPress + レンタルサーバー | サーバー代が中心。ビジネス級でも 36ヶ月契約で月額 **3,960 円** 前後 | サーバーだけで見ると年 **数万円** |

- Hobby の転送量は月 **20GB** で、超過すると API が止まる — 翌月 1 日に戻る。会社サイトの本番には向きにくい
- Team の転送量は月 **200GB** まで込み、超過は **20 円/GB** — Business は月 **1TB** まで込み、超過は **18 円/GB**
- Team も Business も、API の追加は **2,000 円/個**、メンバーの追加は **1,200 円/人**
- メンバー 3 人は制作会社、社内の更新担当、確認者で埋まる — 4 人目からは月 1,200 円で、Business へ上げる理由にはならない
- 段差の正体は、Team の追加料金では買えない機能が Business にまとまっていること — 権限管理、IP 制限、過去バージョンの復元、カスタムステータス、複数環境、技術サポート
- Team **4,900 円** と Business **75,000 円** の差は月 **70,100 円**、年にすると **約 84 万円** — 権限と IP 制限と復元に払う固定費として見る
- WordPress で同じ要件をロールとサーバー設定で満たせるなら、ライセンスの月額はこの崖をまたがない — 代わりに更新と設定の責任が自分に残る

### 作業時間を月額に足す

- WordPress の更新を月 2 時間、時間単価を 5,000 円と置くと **月 10,000 円** — スタンダードのサーバー代より大きい。単価は案件で置き換える
- プラグインの脆弱性対応や、不正ユーザーができたあとの切り戻しは、この 2 時間には入らない — バックアップが無いと、サーバー月額では埋まらない
- microCMS Team は現金が月 4,900 円多い代わりに、コアと PHP の更新作業が自分の一覧から消える — フロントの `npm` 更新とキーの棚卸しは残る
- 置き方の例: Team の 4,900 円と、WordPress のサーバー 1,200 円 + 更新 10,000 円を並べると、現金と時間を足した月額は WordPress 側が上回る
- Business の 75,000 円は、月 10 時間の更新（時間単価 5,000 円で 50,000 円）を WordPress 側に足しても、サーバー代と合わせて下回ることが多い — この帯は、権限と IP 制限と復元が契約条件かどうかで決める
- 保守を外注している場合は、その月額を WordPress 側の行に足す — CMS 利用料が 0 円でも、保守見積もりが Team を超えていれば、現金の比較は逆になる

> 参照: [microCMS 料金プラン](https://microcms.io/pricing) / [料金プランの価格改定（2025年6月）](https://blog.microcms.io/pricing-update-2025-06/) / [エックスサーバー 料金](https://www.xserver.ne.jp/price/) / [Cloudflare Pages](https://www.cloudflare.com/ja-jp/developer-platform/products/pages/)

## どちらに寄せるか

- 更新頻度が低く、公開面に PHP と管理画面を置きたくない、編集者が 3 人前後で互いの操作を見渡せる — microCMS Team と静的配信。月額は **4,900 円** に API とメンバーの追加を足した額が床になる
- 個人の検証や、止まっても困らないサイト — Hobby の 0 円。転送 **20GB** と API キー **1** 個を超える前に Team へ上げる
- ライターと公開者を分けたい、社内 IP 以外から管理画面を閉じておきたい、誤上書きを過去版に戻したい — microCMS なら Business の **75,000 円**。WordPress のロールとサーバー側制限で足りるなら、サーバー月額のまま要件を満たせる
- 監査ログ、SSO、2要素認証の必須化、請求書払いが社内規定にある — microCMS は Enterprise の見積もり。WordPress はプラグインと IdP で組む分、構築と更新は自前
- 会員登録、在庫、予約、サイト内検索のように、リクエストのたびにサーバーで状態を変える機能が中心 — 管理画面と公開を分けても動的な実行環境は残る。WordPress を継続し、更新、WAF、ログイン、バックアップを毎月の作業として見積もる方が構成は単純なことが多い
- ヘッドレス WordPress（フロントだけ静的や別アプリ）でも、管理用の WordPress と PHP はどこかに残る — そのサーバーの更新と WAF はランニングコストに残る

## よくある間違い

### 1. CMS を替えたので公開後の対策は不要、と扱う

- 静的配信で消えるのは PHP と公開サーバー上の管理画面 — API キー、アカウント、フロントの依存関係、描画する HTML は残る
- GET だけのキーでも、公開中のコンテンツは権限の範囲で取れる — 公開前の文章を同じキーで返さない

### 2. サーバー月額と CMS 月額だけを並べて決める

- WordPress の 約 1,000 円と Team の 4,900 円だけを比べると、更新時間が見積もりから落ちる
- Team の 4,900 円と Business の 75,000 円の間は、コンテンツ件数では埋まらない — 権限と IP 制限が要るかどうかが段差
- Hobby の 0 円を本番の見積もりに置くと、転送超過で API が止まった月の説明ができない

### 3. 本番の API キーに WRITE や下書き全取得を付ける

- ブラウザに届いたキーは、利用者が読める — 公式は、CSR では最低限の GET にするか、サーバー側から呼んでキーを隠す、と案内している
- 問い合わせフォームのように書き込みが要る API だけ、個別権限で POST を足し、そのキーはサーバーに置く
- `NEXT_PUBLIC_` やクライアントへ露出する接頭辞の環境変数に、書き込みキーを入れない

### 4. セキュリティ機能の有無を、プラン表の下の方まで見ずに Team で受注する

- 権限管理、IP 制限、過去バージョンの復元、技術サポートは Team の追加料金では買えない
- 要件定義の時点で「誰が公開するか」「社外から管理画面に入るか」「誤公開を戻す必要があるか」を書く — ここが Yes なら月額は 75,000 円の行
- WordPress 案と比較するときは、同じ要件をロールとサーバー設定で満たす費用（作業時間を含む）を隣に置く

## まとめ

- WordPress の攻撃面は公開サーバー上の PHP、管理画面、プラグイン — microCMS と静的配信は、その実行環境を公開面から外す
- 残る対策は、GET と WRITE のキー分離、2要素認証、フロントの依存関係、描画する HTML
- 権限管理、IP 制限、監査、SSO は microCMS では上位プランの機能 — 2要素認証の設定自体は全プラン、必須化は Enterprise
- 現金の月額は、小規模ならレンタルサーバーの **約 1,000 円** が Team の **4,900 円** より小さい
- 更新を月 2 時間、時間単価 5,000 円と置くと WordPress 側に **月 10,000 円** が乗り、Team との大小は逆になりうる — 単価は案件で置き換える
- 権限分離や IP 制限が要ると microCMS は Business の **75,000 円** — 年額で約 84 万円の段差になる。WordPress のロールで足りるならライセンスはこの段差をまたがない
- Hobby は転送 **20GB** 超過で API が止まる — 本番の会社サイトの見積もりは Team 以上で置く
- 会員や予約のようにリクエストごとに状態が変わるサイトは、動的な実行環境の防御と更新がランニングコストに残る
- 対策を揃えたときの最安の内訳は別記事 — [セキュリティを揃えたときの最安プラン](./wordpress-vs-microcms-minimum-plans.md)
