# JIS X 8341-3について — 日本のウェブアクセシビリティ規格とWCAGの対応

## JIS X 8341-3とは

- 正式名称は **JIS X 8341-3:2016「高齢者・障害者等配慮設計指針－情報通信における機器，ソフトウェア及びサービス－第3部：ウェブコンテンツ」**
- Webページだけでなく、ブラウザや支援技術を介して利用するWebアプリケーションなども対象になる
- 読む相手は、企画、設計、デザイン、実装、試験、発注、保守・運用に関わる人
- 本文は **ISO/IEC 40500:2012** と一致し、その内容は W3C の **WCAG 2.0** と同じ
- レベルA / AA / AAAの達成基準と、適合するための要件を定める
- 日本での継続的な運用を支えるため、方針策定から保守までのプロセスと試験方法を附属書（参考）に置いている
- JISは法律そのものではない。調達仕様、組織の方針、契約などから、満たすべき基準として参照される

> 参照:
> - [WAIC — JIS X 8341-3:2016 解説](https://waic.jp/docs/jis2016/understanding/)
> - [日本産業標準調査会 — JIS検索](https://www.jisc.go.jp/app/jis/general/GnrJISSearch.html)

## WCAGとの関係

| 文書 | 内容 | 2026年10月時点の扱い |
|---|---|---|
| WCAG 2.0 | 2008年のW3C勧告 | JIS X 8341-3:2016本文の基礎 |
| ISO/IEC 40500:2012 | WCAG 2.0を国際規格にしたもの | JIS X 8341-3:2016の対応国際規格 |
| JIS X 8341-3:2016 | ISO/IEC 40500:2012との一致規格 | 日本の方針、調達、試験結果で広く参照される |
| WCAG 2.2 | 2023年のW3C勧告 | 現在のWeb実装で併せて見る基準 |
| ISO/IEC 40500:2025 | 2023年10月版のWCAG 2.2を国際規格にしたもの | 2025年に2012年版を更新 |

- **JIS X 8341-3:2016とWCAG 2.0の達成基準は同じ**。JISだけに日本独自の達成基準が追加されているわけではない
- WCAG 2.1と2.2は、モバイル、ロービジョン、認知・学習、ポインター操作などの達成基準を追加した
- 例外として、WCAG 2.2では達成基準4.1.1「構文解析」が廃止された。JIS X 8341-3:2016には、WCAG 2.0由来の4.1.1が残る
- ISO/IEC 40500が2025年に更新されても、発行年を含む **JIS X 8341-3:2016の内容が自動でWCAG 2.2へ変わるわけではない**
- 実務では「JIS X 8341-3:2016のレベルAA」を国内向けの方針・試験に使い、追加でWCAG 2.2のレベルAAまで確認すると、規格上の説明と現在の障壁への対応を両立しやすい
- WCAG 2.2まで実装していても、対象範囲を定めた試験と結果の公開なしに「JIS X 8341-3:2016のレベルAAに準拠」とは表記しない

> 参照:
> - [W3C WAI — What's New in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
> - [W3C — WCAG 2.2 approved as ISO/IEC 40500:2025](https://www.w3.org/press-releases/2025/wcag22-iso-pas/)
> - [IEC — ISO/IEC 40500:2012](https://webstore.iec.ch/en/publication/11570)

| 2008 | WCAG 2.0がW3C勧告になる |
| 2010 | JIS X 8341-3:2010へ改正。WCAG 2.0の達成基準を取り込む |
| 2012 | WCAG 2.0がISO/IEC 40500:2012になる |

| 2023 | WCAG 2.2がW3C勧告になる |

- これにより規格本文を国際規格と一致させながら、日本で続けてきた方針策定・試験・公開の運用を残している

## 規格の構造

| 箇所 | 役割 |
|---|---|
| 箇条1〜3 | 適用範囲、引用規格、用語・定義 |
| 箇条4 | 知覚可能・操作可能・理解可能・堅ろう（牢）の4原則と達成基準 |
| 箇条5 | 適合レベル、ページ全体、プロセスなどの適合要件 |
| 附属書A（規定） | 規格内の用語集 |
| 附属書JA（参考） | アクセシビリティを確保・維持・向上するプロセス |
| 附属書JB（参考） | ページ単位、ウェブページ一式単位の試験方法 |

- **規定**は適合を判断する要件の一部、**参考**は理解や運用を助ける情報
- 附属書JAとJBは参考だが、日本のWebサイトで方針や試験結果を公開するときの実務上の土台になっている
- 達成基準だけを抜き出さず、箇条5の適合要件と附属書Aの定義も読む。たとえば「ウェブページ」「一連のプロセス」「アクセシビリティ サポーテッド」は日常語より狭く定義されている

> 参照:
> - [WAIC — JIS X 8341-3:2016 解説](https://waic.jp/docs/jis2016/understanding/)
> - [WAIC — JIS X 8341-3:2016 関連文書](https://waic.jp/guideline/jis-x-8341-3_2016/)

## 四つの原則と適合レベル

| 原則 | 主に確認すること | 例 |
|---|---|---|
| 1. 知覚可能 | 情報を利用者が知覚できる | 画像の代替テキスト、字幕、見出し構造、コントラスト |
| 2. 操作可能 | 入力方法を限定せず操作できる | キーボード、十分な時間、フォーカス、ナビゲーション |
| 3. 理解可能 | 内容と操作を理解できる | 言語指定、一貫した操作、ラベル、エラーの説明 |
| 4. 堅ろう（牢） | ブラウザや支援技術が解釈できる | 名前・役割・値をプログラムから取得できる実装 |

| レベル | 考え方 |
|---|---|
| A | 最低限。満たさないと利用できない人が生じる基礎的な障壁を扱う |
| AA | Aに加えて満たす、実務で目標にされることが多い水準 |
| AAA | AとAAに加えて満たす最も高い水準。すべてのコンテンツで達成できるとは限らず、サイト全体の一般方針には推奨されない |

- レベルAAは「AAの達成基準だけ」を満たす意味ではない。レベルAとAAの該当する達成基準をすべて満たす
- 自動検査で検出できる項目だけでは判定できない。代替テキストの内容、キーボード操作、一連の手続きなどは人が確認する
- 適合は使いやすさの上限ではない。規格を満たした後も、障害のある利用者を含むユーザビリティテストが役立つ

> 参照:
> - [W3C — Web Content Accessibility Guidelines (WCAG) 2.0](https://www.w3.org/TR/WCAG20/)
> - [WAIC — JIS X 8341-3:2016 対応発注ガイドライン](https://waic.jp/docs/jis2016/order-guidelines/)

## 達成基準だけでは「適合」にならない

箇条5では、達成基準に加えて五つの適合要件を定めている。

1. **適合レベル**: A、AA、AAAのいずれかで、必要な達成基準をすべて満たす
2. **ページ全体**: ヘッダーや外部ウィジェットなど、ページの一部だけを除外して適合とはしない
3. **一連のプロセス**: 購入や申請など複数ページの手続きは、開始から完了までの全ページが満たす
4. **アクセシビリティ サポーテッド**: 達成の根拠にする技術の使い方を、実際のブラウザや支援技術が利用できる
5. **非干渉**: 適合の根拠にしない技術も、キーボードトラップや閃光などでページ全体の利用を妨げない

```html
<!-- 入力画面だけ直しても、確認画面や完了画面を含む手続き全体の適合にはならない -->
<form action="/application/confirm" method="post">
  <label for="name">氏名</label>
  <input id="name" name="name" autocomplete="name">
  <button type="submit">確認画面へ</button>
</form>
```

- フォーム単体ではなく、入力、確認、エラー、完了までを一つのプロセスとして試験する
- チャット、地図、決済など第三者のコンテンツがページ内にあっても、原則としてページ全体の判定から都合よく外せない
- 第三者コンテンツや対応していない言語に対する「部分適合に関する記述」は、ページ自体を適合とみなす仕組みではない

> 参照:
> - [W3C WAI — Understanding Conformance](https://www.w3.org/WAI/WCAG20/Understanding/conformance.html)
> - [WAIC — JIS X 8341-3:2016 解説「部分適合に関する記述」](https://waic.jp/docs/jis2016/understanding/)

## 附属書JA — 一度直して終わりにしない

附属書JAは、アクセシビリティを組織の運用に組み込む流れを示す。

| 段階 | 行うこと |
|---|---|
| 企画 | 責任者、対象範囲、目標レベルを決め、ウェブアクセシビリティ方針を作る |
| 設計 | 達成基準を満たす仕様、テンプレート、コンポーネントを決める |
| 制作・開発 | 仕様に沿って実装し、工程内で確認する |
| 検証 | 達成基準を満たすか試験し、結果を記録する |
| 保守・運用 | 更新で品質を落とさず、方針と試験を定期的に見直す |

- 公開直前に全ページを修正するより、CMSのテンプレート、デザインシステム、入稿ルールへ要件を入れる
- 方針には、第三者が特定できる対象範囲と、目標とする適合レベル・対応度を書く
- 達成期限、例外、担当部署、把握している問題と今後の対応も書くと、継続的な改善を追いやすい

> 参照: [WAIC — ウェブアクセシビリティ方針策定ガイドライン](https://waic.jp/docs/jis2016/accessibility-plan-guidelines/)

## 附属書JB — 何を試験し、何を公開するか

- 単一のウェブページ、または共通の目的を持つ **ウェブページ一式** を単位に試験する
- ウェブページ一式では、全ページを試験するほか、ランダムな選択、代表ページの選択、両方の組み合わせを使える
- 代表ページには、トップ、主要な導線、テンプレートの種類、フォーム、検索結果、重要な一連のプロセスなどを含める
- WAICは100ページを超えるウェブページ一式で、代表ページとランダムページを組み合わせる方法を推奨している
- 40〜50ページは組み合わせる場合の目安であり、代表すべきページが多ければ、その数に機械的に収めない
- 試験結果には、規格番号と改正年、適合レベル、対象、依存したWebコンテンツ技術、試験したページ、試験期間、達成基準ごとの結果などを示す

自動ツールの結果だけを、そのままJISの試験結果にはできない。たとえば `alt` 属性が存在することは検出できても、その文言が画像の目的を代替しているかは人が判断する。

```html
<!-- 属性はあるが、内容の試験では不合格になり得る -->
<img src="mayor-message.jpg" alt="image123.jpg">

<!-- 画像の目的に応じた代替テキストを付ける -->
<img src="mayor-message.jpg" alt="市長が新年度の重点施策を説明している">
```

> 参照: [WAIC — JIS X 8341-3:2016 試験実施ガイドライン](https://waic.jp/docs/jis2016/test-guidelines/)

## 「適合」と「準拠」を分ける

**適合**は規格本文の用語で、規格の要件を満たすこと。これとは別にWAICは、日本のWebサイトが対応状況を示すための表記を定めている。

| 対応度 | 試験 | 公開・追加事項 |
|---|---|---|
| 準拠 | 目標レベルの達成基準をすべて満たす | 方針と試験結果を公開する |
| 一部準拠 | 一部を満たす | 方針を公開し、今後の対応方針を示す。試験結果の公開は任意 |
| 配慮 | 実施の有無、結果を問わない | 方針と、目標レベルまたは参照した達成基準を示す |

- 「準拠」「一部準拠」「配慮」は **WAICが独自に定めた対応度表記** であり、JIS本文の適合レベルではない
- 「レベルAAに一部準拠」にはレベルAへの準拠が前提。「レベルAAAに一部準拠」にはレベルAAへの準拠が前提
- 「準拠予定」と、試験済みの「準拠」を分ける。公開前の目標は、期限と一緒に方針へ書く
- 「JIS対応」「JIS準拠相当」のような独自表現は、対象・レベル・試験の有無が読み手に伝わらない

> 参照: [WAIC — ウェブコンテンツのJIS X 8341-3:2016 対応度表記ガイドライン（2021年4月版）](https://waic.jp/docs/jis2016/compliance-guidelines/)

## 方針と試験結果の書き分け

### 方針に書くもの

```md
## ウェブアクセシビリティ方針

### 対象範囲
株式会社○○のコーポレートサイト（https://www.example.jp/）全体

### 目標とする適合レベル及び対応度
JIS X 8341-3:2016の適合レベルAAに準拠することを目標とします。

### 目標達成期限
2027年3月31日
```

### 試験後に書くもの

```md
## 試験結果

- 規格: JIS X 8341-3:2016
- 満たしている適合レベル: AA
- 対象: https://www.example.jp/ 以下のウェブページ一式
- 依存した技術: HTML、CSS、JavaScript
- 試験期間: 2027年2月1日〜2027年2月28日
- 試験対象ページ: 試験ページ一覧を参照
- 達成基準ごとの結果: 達成基準チェックリストを参照
```

- 方針は将来の目標、試験結果は確認した事実。文書を分けると、未達成なのに「準拠済み」と読まれることを防げる
- 対象外を「一部のページ」のように曖昧にせず、URLやディレクトリ、コンテンツ種別で特定する
- リニューアル後だけでなく、CMS更新、フォーム追加、外部サービス変更の後にも再確認する

> 参照:
> - [WAIC — ウェブアクセシビリティ方針策定ガイドライン](https://waic.jp/docs/jis2016/accessibility-plan-guidelines/)
> - [WAIC — JIS X 8341-3:2016 試験実施ガイドライン](https://waic.jp/docs/jis2016/test-guidelines/)

## JIS 2016だけで止めない

JIS X 8341-3:2016はWCAG 2.0と対応するため、その後に追加された達成基準は含まない。

```html
<!-- 検索件数が変わっても、フォーカスを移さず、支援技術へ変更を伝えない -->
<p id="result-count">12件</p>
```

```html
<!-- WCAG 2.1で追加された4.1.3「ステータスメッセージ」も考慮する -->
<p id="result-count" role="status" aria-live="polite">12件見つかりました</p>
```

- JIS X 8341-3:2016への準拠を維持しながら、WCAG 2.1 / 2.2で追加された要件を方針や調達仕様へ足せる
- 追加分には、表示の向きを固定しない、テキストを拡大してもリフローする、入力目的を特定する、ステータスメッセージを通知する、ドラッグ以外の操作を用意する、ターゲットサイズを確保する、アクセシブルな認証を提供する、などがある
- 何に準拠したかを曖昧にまとめず、「JIS X 8341-3:2016 レベルAA」と「WCAG 2.2 レベルAA」を分けて記録する
- デジタル庁も、JIS X 8341-3:2016とWCAG 2.2の両方を指標にする方針を公開している

> 参照:
> - [W3C WAI — What's New in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
> - [デジタル庁 — ウェブアクセシビリティ](https://www.digital.go.jp/accessibility-statement)
> - [デジタル庁 — ウェブアクセシビリティ導入ガイドブック](https://www.digital.go.jp/resources/introduction-to-web-accessibility-guidebook)

## フロントエンドの実務への落とし方

| 工程 | 最低限残すもの |
|---|---|
| 要件定義 | 対象範囲、JISの発行年、目標レベル、対応度、WCAG 2.2追加分、期限 |
| 設計 | 見出し、ランドマーク、キーボード操作、フォーカス、エラー、動的通知の仕様 |
| 実装 | ネイティブHTMLを優先した共通コンポーネントと、使い方の文書 |
| セルフレビュー | 自動検査、キーボード、拡大、スクリーンリーダーによる主要タスクの確認 |
| 試験 | 達成基準チェックリスト、実装チェックリスト、対象ページと判定根拠 |
| 公開後 | 方針、結果、既知の問題、問い合わせ先、次回の確認時期 |

- 発注仕様に「JISに対応する」だけを書かない。`JIS X 8341-3:2016の適合レベルAAに準拠` のように年、レベル、対応度まで決める
- 成果物にHTMLだけでなく、試験対象ページ一覧、チェックリスト、未解決事項、再試験の条件を含める
- 試験担当だけへ任せず、デザインレビューとコードレビューの完了条件に達成基準を入れる
- 新しいコンポーネントは、JIS 2016の範囲に加えてWCAG 2.2の追加達成基準も確認する

> 参照: [WAIC — JIS X 8341-3:2016 対応発注ガイドライン](https://waic.jp/docs/jis2016/order-guidelines/)

## まとめ

- JIS X 8341-3:2016は、日本で使うWebコンテンツのアクセシビリティ規格で、本文はWCAG 2.0およびISO/IEC 40500:2012と一致する
- レベルA / AA / AAAの達成基準だけでなく、ページ全体、一連のプロセス、アクセシビリティ サポーテッドなどの適合要件も見る
- 附属書JAは方針から保守まで、附属書JBは試験対象の選び方と結果表示を支える
- 「準拠」「一部準拠」「配慮」はWAICの対応度表記。準拠には方針、試験、結果公開が必要
- JIS 2016はWCAG 2.1 / 2.2の追加基準を含まない。国内向けのJIS対応と、現在のWCAG 2.2対応を併用する
