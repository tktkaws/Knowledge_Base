# SSL証明書の種類と選び方 — DV・OV・EV・ワイルドカード

## SSL証明書の認証レベル

- SSL証明書は認証局（CA）が発行する
- 認証レベルによって「何を証明するか」が異なる
- 暗号化の強度はどの認証レベルでも同じ（違いは身元確認の厳格さ）

| 種類 | 認証対象 | 発行までの期間 | 費用 |
|---|---|---|---|
| DV（Domain Validation） | ドメインの所有権のみ | 数分〜数時間 | 無料〜年数千円 |
| OV（Organization Validation） | ドメイン + 組織の実在性 | 数日〜1週間 | 年数万円 |
| EV（Extended Validation） | ドメイン + 組織の厳格な実在性 | 1〜2週間 | 年十数万円 |

- 参照: [GlobalSign — SSL証明書の種類](https://jp.globalsign.com/ssl/about/type.html)

## DV証明書（ドメイン認証）

### 特徴

- ドメインの所有権のみを検証する、最も基本的な証明書
- 自動発行が可能で、取得が最も簡単
- Let's Encryptで無料取得できる
- 証明書にはドメイン名のみ記載（組織名は含まれない）

### 認証プロセス

```
1. 申請者がCAにドメイン名を申告
2. CAが以下のいずれかの方法でドメイン所有権を確認:
   - DNS認証: 指定されたTXTレコードをDNSに追加
   - HTTP認証: 指定されたファイルをWebサーバーに設置
   - メール認証: admin@example.com などに確認メールを送信
3. 確認完了後、証明書を発行
```

### 向いている用途

- 個人ブログ、ポートフォリオサイト
- 小規模なコーポレートサイト
- 開発・ステージング環境
- とにかくHTTPS化を手軽に行いたい場合

### 注意点

- ドメインの所有権しか証明しないため、フィッシングサイトでも取得可能
- 「HTTPSだから安全」とは限らないことをユーザーに理解してもらう必要がある

## OV証明書（組織認証）

### 特徴

- ドメインの所有権に加えて、申請組織の実在性を確認する証明書
- 証明書の詳細情報に組織名・所在地が記載される
- 人手による審査が入るため、発行に数日かかる

### 認証プロセス

```
1. DV認証と同じドメイン所有権の確認
2. 加えて以下を確認:
   - 組織の法的な登記情報（登記簿謄本など）
   - 組織の住所・電話番号
   - 申請者が組織に所属していること（電話確認など）
3. 確認完了後、証明書を発行
```

### 証明書の確認方法

```
証明書の詳細を開くと、Subjectフィールドに組織情報が含まれる:

Subject:
  CN = example.com
  O  = Example Corporation    ← 組織名
  L  = Shibuya-ku             ← 市区町村
  ST = Tokyo                  ← 都道府県
  C  = JP                     ← 国コード
```

### 向いている用途

- 企業のコーポレートサイト
- 問い合わせフォームを含むビジネスサイト
- 組織の信頼性を示したい場合

## EV証明書（拡張認証）

### 特徴

- 最も厳格な審査を経て発行される証明書
- 組織の法的実在性、物理的実在性、運営実態を詳細に確認
- 以前はアドレスバーが緑色に変わる表示があったが、現在は廃止
- 証明書の詳細情報に最も多くの組織情報が記載される

### 認証プロセス

```
1. DV + OVの認証に加えて:
   - 登記簿謄本や第三者データベースでの法的実在性の確認
   - 物理的な事業所の存在確認
   - 申請者の権限確認（代表権限の確認）
   - 電話による直接確認
2. CA/Browser Forumのガイドラインに準拠した厳格な審査
3. 確認完了後、証明書を発行
```

### ブラウザでの表示の変遷

```
2018年以前:
  [Example Corporation] https://example.com  ← アドレスバーに組織名が緑で表示

2019年以降（Chrome 77〜）:
  🔒 https://example.com  ← DV/OV/EVすべて同じ鍵アイコン表示
  ※ 鍵アイコンをクリックすると証明書詳細で組織名を確認可能
```

- Chrome、Firefox、SafariはいずれもアドレスバーでのEV特別表示を廃止
- EV証明書の視覚的な差別化効果は大幅に低下した

### 向いている用途

- 銀行、証券会社などの金融機関
- ECサイト（大規模なオンラインショップ）
- 政府・公共機関のWebサイト
- 業界や規制で要求される場合

- 参照: [CA/Browser Forum — EV SSL Certificate Guidelines](https://cabforum.org/extended-validation/)

## ドメインの対応範囲による分類

認証レベル（DV/OV/EV）とは別に、1枚の証明書がカバーするドメインの範囲による分類がある。

### シングルドメイン証明書

| 項目 | 内容 |
|---|---|
| 対象 | 1つのFQDN（例: `www.example.com`） |
| 特徴 | 最もシンプルで安価 |
| 注意 | `example.com`と`www.example.com`は別扱いの場合がある（SANで両方含めるのが一般的） |

### ワイルドカード証明書

| 項目 | 内容 |
|---|---|
| 対象 | `*.example.com`（同一階層のすべてのサブドメイン） |
| 特徴 | サブドメインを追加しても証明書の再発行不要 |
| 注意 | `*.example.com`は`sub.example.com`に一致するが、`sub.sub.example.com`には一致しない |

```
*.example.com で保護されるドメイン:
  ✓ www.example.com
  ✓ api.example.com
  ✓ blog.example.com
  ✓ admin.example.com
  ✗ example.com（ネイキッドドメインは含まれない場合がある）
  ✗ sub.api.example.com（2階層以上のサブドメインは対象外）
```

### マルチドメイン証明書（SAN証明書）

| 項目 | 内容 |
|---|---|
| 対象 | 複数の異なるドメイン名を1枚でカバー |
| 特徴 | SAN（Subject Alternative Name）フィールドに複数ドメインを列挙 |
| 注意 | ドメイン追加のたびに再発行が必要な場合がある |

```
1枚の証明書で以下をすべてカバー:
  - example.com
  - example.net
  - example.co.jp
  - shop.example.com
```

## 選び方の判断基準

### 認証レベルの選択

```
個人サイト・ブログ                → DV証明書
中小企業のコーポレートサイト      → DV証明書（コスト重視）またはOV証明書
ECサイト・会員制サイト            → OV証明書以上
金融・医療・官公庁               → EV証明書
開発・ステージング環境            → DV証明書（Let's Encrypt）
```

### ドメイン範囲の選択

```
単一ドメインのみ                  → シングルドメイン証明書
サブドメインを複数運用             → ワイルドカード証明書
異なるドメインを複数運用           → マルチドメイン（SAN）証明書
```

### 組み合わせの例

| パターン | 証明書の種類 | 例 |
|---|---|---|
| 個人ブログ1つ | DV + シングル | Let's Encrypt |
| 企業サイト + ブログ + API | OV + ワイルドカード | `*.example.com` |
| 複数ブランドのECサイト | EV + マルチドメイン | `shop-a.com` + `shop-b.com` |

## 主な認証局（CA）

| 認証局 | 特徴 |
|---|---|
| Let's Encrypt | 無料DV証明書。自動発行・自動更新。最も広く利用 |
| DigiCert | 大企業向け。EV/OV証明書の大手 |
| GlobalSign | 日本での実績が豊富。国内サポートあり |
| Sectigo（旧Comodo） | コストパフォーマンスが良い。中小企業に人気 |
| Amazon Certificate Manager | AWS環境で無料利用可能。ALB/CloudFrontとの統合 |
| Google Trust Services | Google Cloud環境で利用可能 |

## 証明書の有効期間

- 2020年9月以降、SSL証明書の最大有効期間は**398日（約13ヶ月）**
- 以前は2〜3年の証明書もあったが、セキュリティ上の理由で短縮された
- Let's Encryptの証明書は90日間有効（自動更新で運用）
- 有効期限切れによるサイトダウンを防ぐため、自動更新の仕組みが重要

- 参照: [CA/Browser Forum — Ballot SC31](https://cabforum.org/2020/07/16/ballot-sc31-browser-alignment/)

## よくある間違い

### 「DV証明書は安全ではない」

- 暗号化の強度はDV/OV/EVすべて同じ
- 違いは「サーバー運営者の身元確認の厳格さ」のみ
- DVでも通信の暗号化は完全に機能する

### 「EV証明書なら信頼される」

- 主要ブラウザがEVの特別表示を廃止したため、一般ユーザーには違いが見えにくい
- EV証明書の価値は「組織の実在性の証明」であり、表示上の差別化ではない

### 「ワイルドカード証明書は万能」

```
; 悪い例: 2階層のサブドメインも保護されると思い込む
*.example.com で sub.api.example.com を保護しようとする

; 良い例: 2階層のサブドメインには別の証明書を用意
*.example.com        → www, api, blog など
*.api.example.com    → v1.api, v2.api など（別途必要）
```

## まとめ

- SSL証明書はDV・OV・EVの3つの認証レベルがある。暗号化強度は同じ、身元確認の厳格さが異なる
- DV証明書はドメイン所有権のみ確認。Let's Encryptで無料取得でき、ほとんどのサイトに十分
- OV証明書は組織の実在性も確認。企業サイトで信頼性を示したい場合に有用
- EV証明書は最も厳格だが、ブラウザでの視覚的差別化は廃止された
- ドメイン範囲はシングル・ワイルドカード・マルチドメインから運用に合わせて選択
- 証明書の有効期間は最大398日。自動更新の仕組みが必須
